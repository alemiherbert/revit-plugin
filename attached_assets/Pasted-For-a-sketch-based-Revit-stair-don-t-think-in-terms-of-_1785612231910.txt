For a **sketch-based Revit stair**, don't think in terms of *runs* and *landings* initially. Instead, think in terms of a **graph extracted from the sketch**, then classify each region. This approach works even for U, L, Dogleg, Open-well, and complex custom stairs.

The image you attached is a good example. The **green lines** are the stair boundaries and the **black lines** are risers. The blue line is the walk line. The algorithm should primarily use the **boundary and riser geometry** because they are always present in sketch stairs.

# Stage 4. Detect riser spacing

Sort risers by position.

Compute spacing.

```
spacing[i] = Distance(riser[i], riser[i+1])
```

Most stair runs have

```
spacing ≈ tread depth
```

This value becomes the "expected tread depth."

```
ExpectedTreadDepth =
Median(spacing)
```

---

# Stage 5. Classify Run vs Landing

This is the key step.

For every region

Compute

```
adjacentRisers

lengthAlongTravel

width

```

### Rule 1

Landing touches **zero risers**

```
adjacentRisers == 0

=> Landing
```

---

### Rule 2

Landing touches only one riser

```
adjacentRisers == 1

=> Landing
```

---

### Rule 3

Run touches multiple evenly spaced risers

```
adjacentRisers >=2

AND

spacing approximately constant

=> Run
```

---

### Rule 4

Run aspect ratio

Runs are long.

```
Length / Width > 1.5
```

Landings tend toward

```
Length ≈ Width
```

---

### Rule 5

Run contains risers

If risers cross the region

```
Run
```

## Recommended C# architecture

Instead of coding this as one large procedure, model it as a pipeline of independent components:

```text
SketchExtractor
    ↓
TopologyBuilder
    ↓
RegionClassifier
    ↓
ConnectivityGraphBuilder
    ↓
StairTraversalSolver
    ↓
ElevationAssigner
    ↓
PanelGenerator
    ↓
AnalyticalModelBuilder
```

Each stage has a single responsibility, making it easier to test and extend. For example, if you later support monolithic, precast, spiral, or winder stairs, you'll primarily modify the `RegionClassifier` and `StairTraversalSolver` while leaving the panel generation logic unchanged. This graph-based pipeline is considerably more robust than relying on geometric heuristics alone because it uses the topological relationships inherent in the stair sketch.
