Since this is **Revit**, you have a major advantage: **you don't need to infer everything from raw geometry.** The `Stairs` element already exposes much of the topology. Instead of trying to detect runs and landings from the sketch alone, leverage the Revit API wherever possible and only fall back to geometry analysis when necessary.

## Recommended workflow

```text
Stairs
    │
    ├── GetStairsRuns()
    │        │
    │        ├── Sketch
    │        ├── Path
    │        ├── Base Level
    │        ├── Top Level
    │        ├── Number of Risers
    │        └── Geometry
    │
    ├── GetStairsLandings()
    │        │
    │        ├── Boundary
    │        └── Elevation
    │
    └── Generate Analytical Panels
```

This is much more reliable than trying to classify regions yourself.

---

# Step 1. Get the stair

```csharp
Stairs stair = doc.GetElement(id) as Stairs;
```

---

# Step 2. Get all runs

```csharp
ICollection<ElementId> runIds = stair.GetStairsRuns();

foreach(ElementId id in runIds)
{
    StairsRun run =
        doc.GetElement(id) as StairsRun;
}
```

Revit has **already determined** what constitutes a run.

---

# Step 3. Get all landings

```csharp
ICollection<ElementId> landingIds =
    stair.GetStairsLandings();

foreach(ElementId id in landingIds)
{
    StairsLanding landing =
        doc.GetElement(id) as StairsLanding;
}
```

Again, no need to detect them manually.

---

# Step 4. Get the sketch

Each run can expose its sketch geometry.

```csharp
Sketch sketch =
    doc.GetElement(run.SketchId) as Sketch;
```

The sketch contains

```
Boundary curves

Riser curves

Path
```

which are exactly what you're seeing in your image.

---

# Step 5. Determine run direction

The walk line already gives the travel direction.

```csharp
CurveLoop path
```

or

```csharp
LocationCurve
```

depending on the run type.

Travel direction

```
Path.Start

↓

Path.End
```

---

# Step 6. Determine slope

You already know

```
Number of Risers

Actual Run Length

Actual Height
```

Therefore

```text
Slope

=

Height

/

Horizontal Length
```

No geometry inference required.

---

# Step 7. Determine elevations

Every run exposes

```
BaseElevation

TopElevation
```

or enough parameters to compute them.

For example

```
Run 1

0 mm

↓

1800 mm
```

Landing

```
1800 mm
```

Run 2

```
1800 mm

↓

3600 mm
```

---

# Step 8. Place analytical panel

For each run

1. Extract boundary polygon.
2. Compute the centerline (or use the path).
3. Construct an inclined plane using:

   * travel direction,
   * local width direction,
   * plane normal.
4. Offset the plane by:

```text
WaistThickness / 2
```

along the **local plane normal**.

This places the panel at the **mid-surface** of the stair waist.

---

# Landing panel

Landing is much easier.

```
Boundary

↓

Horizontal Plane

↓

Offset

↓

Panel
```

# But what if the stair is "By Sketch"?

Even sketch-based stairs are internally decomposed into `StairsRun` and `StairsLanding` elements after creation. The API does not leave them as a single undifferentiated sketch. So for a valid Revit stair, you should still iterate `GetStairsRuns()` and `GetStairsLandings()` rather than attempting to rediscover those regions from sketch lines.

---

## If your tool must operate only on the sketch

If your goal is to reconstruct the analytical model **solely from the sketch geometry** (for example, because you're processing the sketch before Revit creates the stair, or you're intentionally avoiding `StairsRun`/`StairsLanding`), then the graph-based algorithm from my previous message is the correct approach.

However, if you're writing a Revit add-in that runs on an existing `Autodesk.Revit.DB.Architecture.Stairs` element, the preferred algorithm is:

```text
Select Stair
      │
      ▼
GetStairsRuns()
      │
      ├── Extract run boundary
      ├── Get path
      ├── Get width
      ├── Get risers
      ├── Compute inclined analytical plane
      └── Offset to waist mid-surface
      │
      ▼
GetStairsLandings()
      │
      ├── Extract boundary
      ├── Get elevation
      ├── Create horizontal analytical panel
      └── Offset to slab mid-surface
      │
      ▼
Connect panels into one analytical model
```

This approach aligns with Revit's internal representation, is robust across sketch-based, straight, L-shaped, U-shaped, and multi-run stairs, and avoids brittle geometric classification logic.
